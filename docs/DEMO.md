# Демонстрация на 3–5 минут

1. Запустить Compose по README. Войти как `anna@spaceops.demo`.
2. На плане выбрать день в ближайшем будущем, свободную Orbit или Atlas, интервал 10:00–11:00. Задать название встречи, 4 участников и необходимость проектора. Проверить краткое подтверждение и сохранить.
3. В карточке той же комнаты создать обращение «Не включается проектор», указать оборудование и описание. Обращение само по себе не блокирует комнату.
4. Выйти, войти как `mark@spaceops.demo`. В «Support tickets» открыть заявку, взять её в работу. На плане выставить тот же день/интервал, выбрать комнату, нажать «Restrict availability», указать ремонт.
5. Открыть «Operations»: показать ограничение и затронутую встречу. Нажать «Find an alternative», выбрать предложенную комнату того же этажа, отправить предложение.
6. Выйти, снова войти как Anna. Открыть «Bookings», показать предложение и подтвердить. Показать новое помещение в списке и «Relocation accepted» в истории.
7. Показать уведомления. Войти как Mark и снять блокировку; перенесённая встреча остаётся в новой комнате.
8. Кратко показать календарь, мобильный список и аналитику.

## Конкурентный сценарий

```bash
DATABASE_URL=postgres://spaceops:spaceops_local@localhost:5432/spaceops_test npm run test:integration
```

Показать тест «returns one success and one 409 for concurrent overlapping bookings» и тест одновременной блокировки/бронирования. Запросы идут через Supertest в настоящий NestJS API с отдельными соединениями PostgreSQL. Также тестируется прямое нарушение EXCLUDE в БД.

Готовые Playwright-сценарии повторяют основной путь для настольного и мобильного экрана. Запись видео не входит в исходники: её нужно сделать при демонстрации собственного развернутого экземпляра.
